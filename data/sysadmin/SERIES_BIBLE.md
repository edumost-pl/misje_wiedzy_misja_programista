# SERIES_BIBLE — Місія Адміністратор (nonfiction)

## Жанр

Сучасна україномовна **науково-популярна** книга для дітей 10–12 років.  
Взірці: DK, Usborne, No Starch Press, Make: — не шкільний підручник і не повість.

## Головна мета

Після книги дитина: Pi 5 → Linux → термінал → файли → мережі/SSH → Minecraft Server → інтерес до адміністрування й програмування.

## Популяризатор (не підручник)

**Правило:** спочатку **здивувати**, потім називати інструмент.

| Слабко (пояснює) | Сильно (дивує) |
|------------------|----------------|
| «grep шукає текст» | Книга на 800 сторінок — знайди *Minecraft*. Читати всю? Ні. Помічник **grep**. |
| «pwd показує шлях» | Зав’язані очі в чужому будинку — «де я?» → **pwd** |
| «ping перевіряє мережу» | «Ау!» у гори — чуєш луну? → **ping** |
| «одноплатний = слабкий» | Комп’ютер колись займав кімнату — потім кишеню → **одноплатний** |
| «cd змінює теку» | Коридор із табличками — переступи поріг → **cd** |
| «sudo = superuser do» | Двері в щитову зачинені — просиш майстра на хвилинку → **sudo** |
| «server.properties» | Конституція світу без законів — хаос → **server.properties** |
| «Done у логах» | Літак гуде, але двері зачинені — чекай сигнал пілота → **Done** |

Заборонено вводити команду **одним реченням-визначенням**. Спочатку ситуація, в якій читач **сам** відчуває потребу в інструменті — і лише тодім ім’я команди.

## Читання без тиску

- Книга **не втрачає цінності без Pi**: у кожному розділі — блок **«У класі без Pi»** (трек B) з результатом уроку й чеклістом.
- **Трек A** — Pi в руках (`try`); **трек B** — клас, зошит, шкільний ПК, рольові ігри (`class-without-pi.js`).
- **Разом із дорослим** — для сім’ї й гуртка (живлення, мережа, sudo, Java, сервер).
- «Перевір себе»: **3 обов’язкові** + **2 бонусні** питання на розділ (у легких розділах 2+2). Це не іспит.

## Стиль

Науково-популярна книга, **не** підручник Linux.

1. Життєва ситуація (знайома дитині)  
2. Запитання / інтрига  
3. Припущення читача  
4. Пояснення простою мовою + аналогія  
5. Лише потім команда / термін  
6. Практика‑дослідження  
7. Висновок і місток  

Коротко. Без води. Без академії. **Терміни жирним**, команди в `коді`.

## Старт розділу (обов’язково)

Кожен розділ починається з **життєвої ситуації**, не з визначення чи команди.

**Заборонено** починати словами на кшталт: «Команда…», «Процес…», «find…», «grep…», «SSH…», «Linux…», «Термінал…», «IP…».

Спочатку проблема → «У мене теж таке було!» → лише потім інструмент Linux.

**Перевірка:** якщо прибрати всі команди Linux, чи лишається цікава історія? Якщо ні — переписати.

Дитина запам’ятовує не назву команди, а **яку проблему** вона вирішує.

## Методичний ритм розділу (обов’язково)

Кожні 1–2 абзаци — нова емоція або думка дитини:

1. Життєва ситуація / гачок  
2. Голос сумніву читача (*«…?»*)  
3. Одне пояснення за раз (аналогія → термін)  
4. 🤔 think **до** відповіді → reveal пізніше  
5. Жива метафора  
6. Практика 🔍 з чеклістом‑дослідженням  
7. Типові помилки як міф → правда  
8. Короткий підсумок і місток до наступного розділу  

Не випереджати думку дитини. Не звалити всі терміни в першому абзаці.
Не починати з команди. Команда — лише після ідеї.

## Одна таємниця = один розділ (обов’язково)

Кожен розділ відповідає на **одне** головне запитання. Після нього дитина каже: «А тепер я зрозумів саме ЦЕ.»

1. Якщо поняття розкриється детально пізніше — зараз лише інтрига («про це зовсім скоро»).  
2. Повторення дозволене лише як **одне речення-нагадування**, не як нове пояснення.  
3. Практики / `check` / `errors` не вводять теми чужого розділу.  
4. Кінець розділу = місток-цікавість, не спойлер наступної таємниці.
